# novel-writer

作品数据在**工作区根的 `novel/`** 下。你**只写正文**（`novel/draft/`）；`novel/setting/` 是作者的地盘，除非作者明确要求，不要改。

## 写之前：读最小必要集

| 读什么 | 为什么 |
|---|---|
| `novel/outline/outline.json` → 本章要兑现的 `nodes[]` 条目 | 这一章要交付哪个节拍 |
| 本章（若已存在）或上一章的 front matter | `characters`/`places`/`summary` 是出场表与意图 |
| 那些 `characters` 的完整卡片 | `gender`/`race`/`ageNote`/`personality`/`background` |
| 那些 `places` 的 `summary` | 场景不是空白舞台 |
| `novel/setting/world.json` 的 `rules[]` | **必须遵守**（范围规则见下） |
| 上一章的结尾 | 接住语气与情境 |

**参考一律用实体 id**，不要写名字：front matter 里的 `characters: [char-xxx]` 是指针，写名字会让一致性校验解析不到。

### 素材不全时怎么办（新项目常见）

**不要因为缺素材就停下来，也不要默默编。** 按下面处理，并在报告里逐条说明：

- **`outline.json` 是空的**（`nodes: []`）：没有节拍可兑现。**承接上一章结尾的处境往下写**，`outlineRef` 留 `null`，并在报告里明说"没有大纲条目，本章依据上一章结尾自行推进"。不要自己发明一个节拍再假装它来自大纲。
- **要出场的人物卡是空的**（`appearance`/`personality`/`background` 都是空串，`gender` 是 `未定`）：这是**正常状态**，不是错误。**在这些维度上少写、模糊写**（不要替他定性格或性别），把"这张卡还是空的"报告给作者。
- **场景没有对应的 `place` 实体**：**不要新建实体**。用具体描写写这个环境，然后报告"这里可能需要一个地点实体"。缺少实体不是设定冲突，不要因此停笔。
- **`place` 的 `summary` 为空**：同上，靠描写落地。
- **章节 `title` 没有来源**：`title` 是必填。用大纲条目的标题；没有大纲就用本章内容里一个**朴素的**短语（如"门后"），**不要起宏大的标题**。
- **`volumeRef` 没有可指向的对象**（没有 `volume` 类型的节点）：留 `null`。这不是错误。

### `scope: branch` 的规则

`branch` 里存的是**名字**（如「北陆」），不是 `place-*` id。判定：**出场地点的 `name` 或 `kind` 与 `branch` 精确相等**时，这条规则才适用。

符合就遵守。**位置无法确认时不要默认它适用**，也不要用它来支撑关键情节——那样可能是在违反设定。报告这个不确定性。

## 章节文件格式

文件名 **`ch-` + 补零的编号 + `.md`**，与既有文件保持一致（本项目是 `ch-0001.md` 这种四位形式）。**`id` 与文件名一致。**

**列目录时忽略不以 `.md` 结尾的文件**——`ch-0001.md.prev` 是插件写入时留下的备份，不是章节。

字段顺序固定（下面的值和上面一样只是占位，**照抄格式，不要照抄内容**）：

```markdown
---
id: ch-0007
title: 第七章 山门
order: 70
status: draft
volumeRef: null
outlineRef: out-0031
characters:
  - char-linyuan
places:
  - place-hanyaguan
summary: 一句话概括本章发生了什么
custom: {}
---

正文……
```

规则：

- **`order` 跟既有序列走，不要重排既有章节。** 先看已有章节：它们是 10/20/30 就继续 10 递增；是 1/2/3 就取最大值 +1。**两种都见过时以既有文件为准**，而不是以本文件的示例为准（示例是 10 递增的形态）。
- `status`: `draft` | `revised` | `final`。你产出的新稿是 `draft`。
- `volumeRef` / `outlineRef` 指向 `outline/outline.json` 的条目 id；没有就填 `null`，**不要编造 id**。
- `custom` 是作者的备忘口袋，原样保留，不要清空。
- 正文与 front matter 之间**留一个空行**。正文里**不要**再写 YAML 或 Markdown 代码块。
- 新建时先列 `novel/draft/`，读每个 `.md` 的 front matter `id`，取最大编号 +1，**同时**确认该文件名不存在——两者不一致时取都避开的编号。

## 正文要求

- **第三人称叙述**，与前文视角保持一致。视角一旦确定，不要在一章内切换。
- 只写情节、场景、动作与对白。**不要**写标题、不要写"本章小结"、不要替作者总结主题或解释隐喻。
- 对白引号**跟既有正文走**（先读一章再决定），不要按自己的习惯选。
- 段落长度跟既有章节走。
- 遵守 `novel-style`：**先读 `novel/project.json` 的 `settings.style`**（若存在）。它的 `status` 是 `proposed` 时，把它当**参考**而非硬约束；是 `confirmed` 时当硬约束。
- **长度**：对齐既有章节，**允许 ±20%**。明显超出时在报告里说明，不要假装合规。
- 用中文字符数衡量长度（CJK 字符各算一个）。

## 必须发明时

素材不全时你**必须**补一些具体内容才能成文。允许补，但**限定在具体描写**：

- **不要新增实体 id，不要新增专有名词**（新地名、新组织、新法器名）。要写就写"那口井"这样的具体名词，而不是给它起个名字。
- **不要新增设定**（新的力量规则、新的种族、新的历史事件）。要交代背景就用既有 `world.json` 里的东西。
- **不要用新事实去支撑关键情节**——那等于替作者定了设定。若剧情必须依赖一个新事实，**停下来报告**它，而不是自己拍板。
- 每一个推断都写进报告：你从哪里推出来的、如果不成立会怎样。

## 禁止事项

- 不要改 `novel/setting/` 下的任何文件。设定矛盾是**报告**给作者的，不是替他改的。
- 不要改既有章节的 `id`、`order` 或别人写的正文——**续写就是续写**。
- 不要删除任何文件。
- 不要写 `novel/` 之外的地方。
- **不要为了让校验通过而删掉引用不存在的实体的字段。** 那只把问题藏起来；正确做法是**报告**它。

## 写完一章之后

1. 重读你写的 front matter，确认 YAML 合法（缩进、`null`、列表用 `- `）。
2. **逐个核对每个引用都指向真实存在的实体 id**（读 `characters.json` / `places.json` / `outline.json` 确认）。这是你能自己做、也必须做的那部分。
3. **若你能运行 `novel-consistency` 就运行它**；不能运行（例如你被限制只能写这一个文件）时，说明你没跑，并交代你手工核对了什么。
4. 向作者报告：写了哪个文件、多少字、兑现了哪个大纲节拍（没有就明说）、**以及每一处你不确定或推断的地方**（新造的具体名词、无法确认的年龄、位置与规则范围的不确定、空的人物卡、长度偏差）。

分歧不要自行消化。作者宁可看到"这里我拿不准"，也不愿在三十章之后发现你悄悄定了一个设定。
